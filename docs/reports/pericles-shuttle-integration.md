# District A experimental shuttle integration

This branch adds a provisional single-track railway behind the existing District A placeholder station, **not** the final network or a finished game. The city generator opens a rear concourse doorway, adds a shallow ramp, a platform, canopy, benches and tactile edge, and extends the planned walking route to the platform. The generated route centerline is 1,718.5 studs in X/Z, not a measured humanoid walk. The platform and track datum use the ratified platform height and track-center setback numbers. The final Central station design and the network's coordinate frame still require reconciliation.

A separate `ExperimentalRailway` server script builds a straight test track and a procedural two-car placeholder train, with a driver-seat prompt and controls. Server intent is accepted only from the seated character, is rate-limited, and passes finite-value/direction validation. The pure train simulation includes command timeout, reverse-change and door interlocks and a track-end brake/fallback. The button panel is shown only for a locally seated driver. This is experimental, not signalling or production-grade authorization, and does not implement passenger boarding, door animation, a second station, scheduling, multiplayer separation, saving or the imported EMU-1.

The city builder's plan counts **10,343** parts; the separate track/train recipe is about **655** more (630 sleepers). These figures are estimates, not mobile profiling or draw calls. The extra train geometry is not included in `CivitasWorld.GeneratedPartCount`; the railway logs its own count and has a separate `GeneratedPartCount` attribute.

`tools/world/render_station_shuttle.py` generates an approximate station and train concept from exported plan coordinates. It is not a Roblox screenshot. The result is a readable test-blockout concept, not final production architecture or art.

`tools/verify.sh` runs formatting, lint, Luau analysis of client, world, and railway scripts, pure train/security tests, city geometry tests, renders and builds. A passing build does **not** prove runtime. In particular, seat carrying via anchored `Model:PivotTo`, prompting, train-seat physics, collision/ramp seams, streaming, mobile UI, performance and multiplayer remote behavior have not been tested in Studio. The in-game playtest checklist is in `PLAYTEST.md`. Do not call the shuttle playable until those tests pass.
